# Spike

1. State the decision the spike must enable and the cheapest decisive evidence that would answer it.
2. Separate empirical questions from product choices.
3. Build or run only enough to test the uncertain assumption; avoid production architecture around unproven behavior.
4. Record exact inputs, commands, outputs, and environmental constraints.
5. Challenge the result with one alternative explanation or negative case.
6. Conclude `supported`, `not supported`, or `inconclusive` and explain what evidence would change the conclusion.
7. Clearly identify disposable artifacts. Remove temporary files unless the user asks to retain them.
